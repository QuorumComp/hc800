# MEGA65 board

HC800 on the MEGA65 (Artix-7 `xc7a200tfbg484-2`). Headless Vivado build,
driven from the repo root by the `hc800/Makefile` dependency graph
(stages rebuild only when stale), wrapped by `hc800/.justfile`.

## Build

```bash
just bitstream        # RTL regen -> synth -> place -> route -> write_bitstream (each stage skipped when up to date)
just synth            # stop after synthesis (fast compile check, skipped when up to date)
just rev=r3 bitstream # R3 board constraints (default: r6)
just blast            # build, then blast the bitstream into the board's FPGA via JTAG
just clean            # delete the generated Vivado project
```

Bitstream: `build/Mega65Hc800/Mega65Hc800.runs/impl_1/Mega65Top.bit`

Prerequisites: the Vivado env (`/home/ces/Xilinx/vivado_env.sh`, see
`/home/ces/Xilinx/README.md`). `just` sources it itself.

## Programming the board (`just blast`)

`just blast` builds the bitstream, then blasts it into the FPGA over JTAG
with [openFPGALoader](https://github.com/trabucayre/openFPGALoader)
(`pacman -S openfpgaloader`). This is a **volatile SRAM load**: the design
runs until the next power cycle, which restores the stock MEGA65 core.
The recipe never writes the config flash — that would replace the MEGA65
core + hypervisor.

Hardware: a JTAG adapter on the 12-pin header inside the case (the Trenz
TE0790-03 the MEGA65 was designed for; see the MEGA65 Welcome Guide,
"Using the JTAG connector"). The default cable model is `digilent` (the
TE0790's FT2232); override it with `just cable=usb-blaster flash`.
If the loader reports a permission error, install the openFPGALoader udev
rules or run the printed command once with `sudo`.

## Design sources

| File | Origin |
|---|---|
| `hc800_mega65.v` + `*.bin` | generated by SpinalHDL (`just rtl` = `sbt runMain hc800.HC800TopLevel`), checked in |
| `Mega65Top.v` | board wrapper: clock wizard, main memory, HDMI/VDAC, keyboard I/O |
| `mega65kbd_to_matrix.vhd`, `kb_matrix_ram.vhd` | MEGA65 keyboard matrix |
| `../common/hdmi/**` | shared HDMI encoder (`xilinx/` variant used, `altera/` ignored) |
| `ip/*/*.xci` | Xilinx IP: block RAMs (`blk_mem_gen`) + `clk_wiz` clock wizard |
| `mega65r3.xdc`, `mega65r6.xdc` | pin/timing constraints per board revision |

The `.bin` files initialize the boot ROM, kernel and font memories
(`$readmemb` in the generated Verilog). They are regenerated together with
the Verilog — `just bitstream`, `just synth` and `just blast` do this
automatically, or run `just rtl` on its own after changing the firmware.
`just rtl` re-runs sbt only when a Scala/build source or one of the data
files it reads at runtime (`firmware/boot/boot.bin`,
`firmware/kernel/kernel.bin`, `data/font.bin`, `data/box.bin`) is newer
than the generated artifacts.

## Generated files

- `ip/*/` — IP output is generated next to each `.xci` (`gen_directory: "."`).
  Only the `.xci`/`.xml`/`_ooc.xdc` are tracked; the rest is gitignored.
  The build upgrades the cores to the installed Vivado version, which edits
  the tracked `.xci`/`.xml` in place the first time you build with a newer
  Vivado — commit that, it is a one-time change per tool release.
- `build/`, `.Xil/` — the Vivado project created by `build.tcl`. Gitignored,
  safe to delete (`just clean`).
- `Mega65Hc800.xpr` is the legacy in-place GUI project; the headless build
  does not use it. Open it only if you want the Vivado GUI, and expect the
  IP to be upgraded in place.

## Knobs

All build settings are `cfg(...)` variables at the top of `build.tcl`. Each
also accepts an environment override: `MEGA65_REV`, `JOBS`, `BITSTREAM`
(`0` = synthesis only), `CLEAN` (`1` = delete the project dir first).
